# Remote Control Agent v0.1.26-rc.1 — Protected Browser Handoff Candidate

This prerelease adds a narrowly scoped, authenticated human takeover of an existing Windows Agent-owned Chrome/Edge browser session for login and OTP tasks.

- `browser_handoff_request`, `browser_handoff_status`, and `browser_handoff_return` use the existing signed paired-device transport and owner-authorized MCP surface. The Agent never accepts a caller-supplied email address or uncontrolled shell action through these tools.
- The handoff uses an isolated browser profile and an ephemeral Cloudflare Quick Tunnel protected by Cloudflare Access email OTP. The Agent requires a genuine anonymous Cloudflare authorization challenge (including expected redirect and state cookie) and an anonymous POST rejection (HTTP 401) before exposing the one-time link.
- Human browser control has a bounded lifetime and requires an explicit return to AI. Stale browser references are invalidated and cleanup must be confirmed; uncertain state fails closed. Secrets, passwords and cookies are not returned as ordinary browser tool data during human takeover.
- The bounded protected Tunnel readiness window is **90 seconds**, increased from 35 seconds after real Windows network tests revealed delayed dynamic DNS propagation and TLS readiness. The original challenge and POST security proof remain mandatory.
- The corresponding Remote Control Worker uses a **150-second** one-shot handoff request budget while keeping ordinary status and explicit return budgets unchanged. See [mcp-workers PR #308](https://github.com/lirtual/mcp-workers/pull/308).
- The Agent package preserves the existing device identity and supports the existing transactional Windows scheduled-task upgrade and rollback path; no existing device is upgraded by publishing this release.
