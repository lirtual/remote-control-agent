# Remote Control Agent v0.1.18

Restore a missing Windows cloud device grant without reinstalling or rotating the
original Ed25519 private key.

- Existing Windows upgrades still use `irm https://rca.lirtual.dpdns.org/install.ps1 | iex`; the verified package is installed side by side and switched only after explicit Yes.
- New explicit Windows command `rca re-pair --endpoint https://rca.lirtual.dpdns.org/` requires a protected existing private key and device ID plus a validated stopped, current-user task. Older tasks without saved install-mode metadata are supported. Recorded temporary mode is refused.
- First verify a signed cloud grant by the original public key; if already approved under another ID, restore that ID without registering a new grant. Only a 404 starts pending enrollment using the SAME private key.
- One human owner approval through authenticated MCP pairing_lookup / pairing_approve is mandatory for a new grant. HTTP 401/403, throttling, transport faults or timeout fail closed without modifying local identity.
- Commit a new signed ID only after sealing its Windows private ACL and rechecking that the task did not start during the approval window. Preserve the old ID upon staging/seal failures; never modify the private key or cloud approval automatically.
- No silent task restart. After owner approval, start and verify the device over signed WSS and perform a harmless authorized read.
- Native CI tests include the Windows real ACL/staging rename fixture, negative paths, concurrent task restart, and full Windows browser/full tools plus Linux x64/ARM64 packaging. A new Release does not itself modify an installed device.
- Release and Worker pins are published through existing GitHub Actions; the production Worker remains protected at /mcp.
