# Remote Control Agent v0.1.17

One-command Windows upgrade confirmation UX fix.

- For existing paired Windows devices, the public one-line PowerShell installer now uses the PowerShell host selection UI rather than reading a yes/no line from stdin inside an `irm ... | iex` pipeline.
- The dialog displays an explicit Yes / No choice, with **No as the safe default**. Selecting No exits normally without a red PowerShell exception; an unavailable/non-interactive host fails closed.
- Only an affirmative choice allows the verified side-by-side install and existing transactional `rca upgrade` task switch. The device private key, ID, grant, Worker endpoint, task identity and previously stopped/running state remain preserved. New package SHA-256 and GitHub source tag checks are unchanged.
- Fresh Windows installations continue the existing interactive owner pairing flow. Linux x64 and ARM64 binaries retain existing behavior.
- This immutable Release does not modify running devices. The public Worker must separately pin and deploy its source SHA-256 and the three official release assets.
- Source CI (Windows native, Linux x64 and arm64) passed in Agent PR #29. A real user console Yes path and signed WSS/harmless read are still separate acceptance requirements.
