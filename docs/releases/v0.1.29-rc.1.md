# Remote Control Agent v0.1.29-rc.1 — protected iPhone handoff HTTP diagnostics

This is a narrowly scoped **diagnostic prerelease** for [Spec #280](https://github.com/lirtual/mcp-workers/issues/280). The actual iPhone Safari test still completes Cloudflare email OTP but displays a black `{}` page instead of the browser controller. Previous `v0.1.28-rc.1` did not resolve that failure. **This release does not claim to fix the iPhone OTP defect.**

## Change

- Add only bounded, in-memory `diagnostic_code` literals to the existing authenticated `browser_handoff_status` tool for controller-document GET, controller script, one-time exchange and rejected requests. No URL, Host, token, cookies, headers, OTP, screenshots, browser page or keystrokes are exposed.
- Detect an unexpected `POST /.cloudflared/qt-auth/callback` reaching the local controller and emit a fixed diagnostic code while preserving its normal **403 rejection**. Cloudflare still owns email-OTP callback handling.
- Bind controller diagnostics to the current handoff generation, so a delayed event from an explicitly returned old controller cannot overwrite the next handoff's diagnostic state. Clear diagnostic state on explicit return.
- No Worker, authorization policy, new public MCP tool, service, database, proxy, OTP bypass or persistent request logging. Prior one-use link, 15-minute timeout, strict origin/Host/CSRF checks and explicit return remain unchanged.

Implementation: [Agent PR #48](https://github.com/lirtual/remote-control-agent/pull/48), squash-merged into `main` as `89d44561a4d904db55935a6cc898103513ee9fa9`. **Independent human security review: Waived / Not performed by owner authorization; NOT Pass.** Automated PR and main CI, native Windows protected Quick Tunnel challenge and GitGuardian secret scan are separate, limited evidence; they do not establish real-device OTP success.
