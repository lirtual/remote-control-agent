# Remote Control Agent v0.1.30-rc.1 — Quick Tunnel OTP callback failure diagnostics

This is a strictly **diagnostic prerelease** for [Spec #280](https://github.com/lirtual/mcp-workers/issues/280), intended to distinguish selected protected Quick Tunnel OTP callback failures. The most recent real iPhone Safari test on `v0.1.29-rc.1` passed email OTP, then returned literal `Bad Request` while the Agent still reported `diagnostic_code=awaiting_document`. **No real-device proof that the defect is fixed exists.**

## Changes

- Reuse the existing authenticated `browser_handoff_status.diagnostic_code` to expose a bounded allowlist of fixed categories from **cloudflared's existing WARN-level structured pre-origin authorization-failure messages**: missing callback-state Cookie, invalid/mismatched callback state, expired state, malformed callback request, and rejected login initialization.
- Consume cloudflared structured stdout/stderr lines inside the already owned tunnel process; never persist or relay the raw log lines, raw error strings, hostname, OTP, assertion, cookies, query/return path, tunnel URL or browser content. Do not turn on debug logging.
- Keep existing handoff-generation binding and explicit-return diagnostic reset. Unknown or successful auth events remain unasserted: **absence of a WARN diagnostic does not prove authorization succeeded**.
- Serialize only the existing Windows native PowerShell integration test relative to concurrent Windows smoke suites; preserve its original 7-second output assertion and all safety checks. This addresses observed Windows CI scheduler contention without changing production behavior.

No changes to Cloudflare's OTP, `--allowed-mail`, paired-device authorization, Quick Tunnel verification, one-use URL, 15-minute deadline, controller Host/Origin/CSRF checks, device-wide blocking, explicit return, or Worker services. No new API, stored secrets, middleware, proxy or data store.

Implementation: [Agent PR #50](https://github.com/lirtual/remote-control-agent/pull/50), squash-merged into `main` as `6a8c76907441d97cf69aebfbeb78194712fcdbfd`. Independent human security review: **Owner-approved Waived / Not performed**, **not Pass**; approval and limitation are recorded on the PR. Automated CI and Secrets Detection are separate limited checks.

## Release and remaining acceptance

Release only through the official immutable pinned-release workflow, with a successful **main** `workflow_dispatch` candidate run whose HEAD exactly matches the merged source SHA, all three final inner-archive SHA-256 values, and matching GitHub Release assets/tag. PR-branch CI artifacts are not eligible for promotion.

The live Windows device must be upgraded only via the existing owner-interactive, Release-SHA-256-pinned installation procedure, preserving identity. Then run **one** controlled iPhone Safari OTP handoff; on any `Bad Request` or blank response, read `browser_handoff_status.diagnostic_code` **before explicit return** and confirm tunnel cleanup. If the controller opens, verify one human browser action, explicit return, fresh tab identities and no leftover temporary grant. Keep Spec #280 **OPEN / real iPhone acceptance FAIL** until this succeeds.
