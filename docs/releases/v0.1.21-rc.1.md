# Remote Control Agent v0.1.21-rc.1

Application-layer browser network defense in depth for the Agent-owned Windows Chrome/Edge session.

- Start a local per-session DNS-pinned HTTP/HTTPS CONNECT proxy before browser startup. Each request or redirect resolves the destination, refuses private/special IPv4 and IPv6 (including mixed DNS answers), and connects only to a checked numeric address without a second DNS lookup.
- Constrain Chromium's proxy fallback, QUIC and non-proxied WebRTC UDP; maintain the Agent-private browser Profile and leave personal Chrome/Edge settings, OS firewall and system proxy unchanged.
- Close the proxy immediately on browser shutdown/revocation, including while a Chromium Context close is stalled. Revoke new and in-flight browser actions; deny publication of a session started after revocation.
- Independently pin and verify the compiled browser manager, proxy and IP policy files in the Windows package.

**Security scope:** These are best-effort, application-layer mitigations, **not** strict process-level SSRF or TCP/UDP egress isolation. Publicly addressed on-link IPv6/LAN destinations, untested browser subprocess/extension traffic and certain WebTransport/TURN paths remain outside verified confinement. Strict OS-enforced proxy-only isolation remains open in [Issue #33](https://github.com/lirtual/remote-control-agent/issues/33).

Production acceptance requirements: verify Windows public HTTPS, refusal of synthetic local destinations, normal browser close, unexpected browser exit, version/identity preservation and rollback. Do not install privileged WFP services or global network policies.
