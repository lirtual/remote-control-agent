# Remote Control Agent v0.1.22

- Existing permanently paired Linux signed-WSS Agents can upgrade directly using the pinned Linux installer with an explicit `--upgrade`. The previous three-service cutover and its separate `MIGRATE-REMOTE-CONTROL` confirmation are removed.
- Existing installations keep their current systemd service filename; new installations use `remote-control-agent.service`. Runtime descriptions and environment names are normalized without rotating the original device key, changing the device ID, or discarding durable operation receipts.
- A live Agent must approve the existing same-key local quiescence/freeze handshake before the service switch. Busy or uncertain work, foreign unit overrides, mismatched programs or identities, and unsupported upgrades are refused.
- The installer preserves the prior service unit for failure rollback, uses atomic replacement, and leaves recovery evidence if rollback cannot be established. Linux Archive SHA-256 verification and immutable Release checks still run before its executable is used.
- Regular installation cannot silently start a second signed service against an existing historical signed installation. The old loopback/Tunnel unit dependency and dedicated migration program are no longer included.
- Windows keeps its independent signed-device/task upgrade flow; no change to its public installer pin is required for the Linux deployment.
