# Remote Control Agent v0.1.21-rc.2

Application-layer browser network security enhancements and a production-device Fake-IP compatibility fix.

- Keep DNS-pinned per-session HTTP/HTTPS proxy, private/special IPv4/IPv6 refusal, redirect revalidation, private Chrome/Edge Profile and fail-closed browser shutdown/revocation protections from v0.1.21-rc.1.
- When **all** system DNS answers are IPv4 synthetic `198.18.0.0/15` Fake-IP addresses (as seen on some Windows TUN configurations), use authenticated HTTPS public DNS to obtain a genuine public A/AAAA answer. Reapply the unchanged IP allow-list before dialing the numeric address.
- Mixed answers, local/private addresses, malformed DoH responses, DoH failure or timeout still deny the request. No system proxy modification, blanket Fake-IP whitelist, WFP rule, privileged helper or permanent service.
- Added regression coverage and independently pinned the compiled Windows egress policy module.

**Security boundary:** Application-layer defense in depth, **not** strict per-process TCP/UDP SSRF isolation. Strict Windows OS enforcement remains Open in [Issue #33](https://github.com/lirtual/remote-control-agent/issues/33).

Production acceptance: validate direct Chrome/Edge browsing on the actual Windows device using the pinned candidate and retain the previous v0.1.20 package as rollback target before any task switch.
