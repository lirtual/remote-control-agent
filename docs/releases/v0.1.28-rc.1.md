# Remote Control Agent v0.1.28-rc.1 — iOS OTP handoff controller compatibility

This prerelease narrowly addresses the iPhone Safari acceptance failure in [Spec #280](https://github.com/lirtual/mcp-workers/issues/280). In the v0.1.27-rc.1 real-device test, Cloudflare email OTP succeeded but Safari displayed a blank black `{}` response rather than the browser controller; the Agent stayed `link_ready`, not `interactive`. The one-time tunnel was explicitly revoked, and the Agent returned to `ai` without reusing the token.

## Change

- Allow the Agent-owned local handoff controller to accept exactly the observed public HTTPS Quick Tunnel `Host` **or** its actual `127.0.0.1:<listener-port>` authority, to support origin forwarding through `cloudflared`. Arbitrary hosts and forwarded-host overrides remain rejected.
- Add regression coverage for Safari's post-OTP GET HTML/JavaScript through both exact hosts, negative host/path cases, a single `/exchange`, browser Origin, cookie and CSRF checks, and read-only tabs.
- Do not change Cloudflare OTP, strict anonymous GET 302 state-cookie plus POST 401 proof, one-use link claim, session binding, human input grammar, 15-minute expiry, explicit return, paired-device authorization, or any Worker.

The Host-forwarding explanation remains a *working hypothesis*, not a captured production HTTP trace. Passing CI is not proof that the actual iPhone problem has been fixed.

Agent PR: [#46](https://github.com/lirtual/remote-control-agent/pull/46), squash-merged to `main` as `b7d95da55ea16ae94ff4ececfacabc704d9b15cd`.

The official release must pin a completed **main** workflow_dispatch candidate run, all three SHA-256 assets, and this source commit. The official Release Pin workflow must verify and publish immutably before the designated Windows device is upgraded using the interactive, owner-confirmed installer. No CI, merge, or official release represents completed iPhone acceptance.

## Remaining acceptance

On the designated Windows device, verify signed WSS and existing paired identity, then perform real iPhone Cloudflare email OTP, obtain the actual controller UI (not `{}`), conduct one human browser action, explicitly return control, refresh tab identities/snapshot and confirm no temporary tunnel remains. Preserve failure/uncertain outcomes as failed or blocked, not passed. Do not close Spec #280 before this succeeds.
